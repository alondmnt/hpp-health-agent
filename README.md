# hpp-health-agent

Companion code for the HPP Personal Health Agent (PHA) preprint — the metabolic
health agent built on the Human Phenotype Project (HPP). It is a **minimal
implementation** of the architecture the paper describes — a ReAct
orchestrator over domain-expert tools, a ReAct analyser bounded by artifact
accessors, declarative skills, and an eval harness — running end to end on
**synthetic** data.

## Quickstart

```bash
pip install -e .
export ANTHROPIC_API_KEY=...

python run_report.py
```

That writes `out/report.md`, `out/cgm_daily.png` and an execution trace. Any
LiteLLM-supported provider works — copy `llm.json.example` to `llm.json` and
change the model strings.

Prompts live in `prompts/`, not in the code.

```bash
python run_report.py --prompt prompts/meal_grounded_action.md
```

See `prompts/README.md` for what each prompt produces.

The skills layer can be ablated, which is how the paper measures its
contribution (§6.2):

```bash
python run_report.py --skills                              # no skills
python run_report.py --skills clinical-language-guard      # guard only
```

## Example output

[`examples/report.md`](examples/report.md) is a real, unedited run, committed so
you can read the output without credentials. It declines most of what its prompt
asked for, and says why — see the note at the top of that file.

## Architecture

```
run_report.py
      │
      ▼
  ReactOrchestrator ── iteratively selects and calls tools
      │                 tools return ~10 scalars + an artifact ID;
      │                 DataFrames and figures go to the artifact store
      ▼
  ReactAnalyzer ────── writes the report narrative, reading artifacts
      │                 through bounded accessors only:
      │                 get_metric, list_metrics, df_head(n≤100),
      │                 df_schema, text_read(max_chars≤50000)
      ▼
  Reporter ─────────── deterministic. Markdown + CGM figure. No LLM.
```

Skills are markdown files injected into the orchestrator and analyser prompts.
The agent has no implicit tool registry: whatever you pass to `Agent(tools=...)`
is exactly what it can call.

| Layer | Location |
| --- | --- |
| Agent core | `pha/programs.py` |
| Artifact store and accessors | `pha/artifact_store.py`, `pha/artifact_accessors.py` |
| Tool contract | `pha/tool_decorator.py` |
| Tools | `tools/{cgm_parser,cgm_metrics,meal_parser,diet_qc}/` |
| Skills | `skills/*.md` |
| Evals | `evals/` |
| Synthetic data | `data/` |

## Tools

| Tool | Does | Based on |
| --- | --- | --- |
| `cgm_parser` | Parse and validate CGM CSV; unit conversion, gap and cadence profiling | — |
| `cgm_metrics` | 55 clinical CGM metrics, global and per-day | [iglu](https://github.com/staskh/iglu_python) (Broll et al. 2021) |
| `meal_parser` | Ingest and standardise a diet log | — |
| `diet_qc` | 16 deterministic validators over the diet log, rolled up into a per-row severity | Atwater factors; range and consistency checks |

`diet_qc` is the rule-based half of the hybrid QC tool described in the paper;
its two LLM validators are not included here.

## Skills

Three skills ship, exercising both injection points as the full system does:

| Skill | Injects at | Role |
| --- | --- | --- |
| `clinical_language_guard` | analyser | guard: forbidden diagnostic and alarmist terms |
| `diet_qc_guard` | orchestrator + analyser | workflow: run QC after parsing, then report severity honestly |
| `metabolic_health_report` | analyser | report structure, voice, and the grounding contract |

## Evals

```bash
python -m evals.core.runner list
python -m evals.core.runner run --report out/report.md \
    --ground-truth data/synthetic_001/ground_truth.json \
    --config evals/eval_config.yaml
```

| Eval | Type | Checks |
| --- | --- | --- |
| `eval_numerical` | deterministic | Reported values match tool output within a rounding epsilon |
| `eval_critical_cgm_metrics` | deterministic | The mandatory metrics are present with values |
| `eval_clinical_language` | regex | No diagnostic or alarmist terminology |
| `eval_groundedness_llm` | LLM judge | Event claims carry date references |

## Synthetic data

`data/synthetic_001/` is generated by `data/make_synthetic_data.py` with a fixed
seed and is committed so the repo runs out of the box. No real participant data
appears anywhere in this repository.

```bash
python data/make_synthetic_data.py --days 21 --seed 7   # regenerate or vary
python run_report.py --write-ground-truth               # recompute ground truth
```

Fourteen days at 15-minute cadence: a circadian baseline with a dawn rise, plus
a post-prandial excursion after each logged meal scaled by its carbohydrate
content and a per-meal response gain. Three rows of the diet log are
deliberately corrupted so `diet_qc` has genuine findings to report — a clean log
would make the tool contribute nothing to the demo.

## Methods

- CGM metrics are computed with [iglu-python](https://github.com/staskh/iglu_python),
  a port of iglu (Broll et al., 2021).
- Consensus glucose target ranges are from Battelino et al., *Diabetes Care*, 2019.
- Diet-log energy consistency checks use the Atwater factors.
